10-Day Build Plan

Custom Form Builder — Shopify App

Version 1.0  ·  Prerequisites, Daily Milestones & AI-Agent Build Instructions





How to Use This Document

This plan turns the three PRDs already written — Admin Dashboard PRD v1.0, Form Design & Styling PRD v1.0, and Theme Editor Experience PRD v1.0 — into a 10-day, day-by-day build sequence.

Section 1 lists everything that must come from you (accounts, keys, credentials) before Day 1 can start, and exactly where to find each one.

Section 2 sets realistic scope: a solo build with an AI coding agent (e.g. Claude Code) in 10 days produces a working MVP covering Free + Starter tier features end-to-end, with Growth-tier features (conditional logic, rating/signature fields, integrations) stubbed or simplified. Full production hardening and Shopify App Store review prep are listed as Day 11+ follow-on work.

Section 3 is the day-by-day plan. Each day is written as a direct instruction block you can paste to an AI coding tool as-is — objective, concrete tasks, files/commands touched, and a "done when" checkpoint so you can verify progress before moving to the next day.

2.  Scope & Assumptions for the 10-Day Build

Target: a working, installable app on your development store — Theme Editor form creation + Admin Dashboard management, covering Free and Starter tier features fully.

Growth-tier features (conditional logic, Rating/NPS, Signature field, live third-party integrations) are built as real UI with plan-gate locks per the PRDs, but their backend logic can be simplified/stubbed in the 10-day window and completed after.

One field type family is treated as the reference implementation (Text Input) and the rest are built by extending it, per the Theme Editor PRD Section 4 inheritance notes — this is what makes 17 field types feasible in the timeframe.

Each day assumes ~1 focused build session with an AI coding agent (e.g. Claude Code) executing the tasks, with you reviewing/testing the "done when" checkpoint before moving on.

App Store submission polish, load testing, and the optional integrations are listed as Day 11+ in Section 4.





3.  Day-by-Day Build Plan

Each day below can be copy-pasted directly to an AI coding agent as its working brief for that session.



DAY 1   Environment & Shopify App Scaffolding

OBJECTIVE

Stand up a runnable, installable Shopify app skeleton connected to the dev store.

TASKS

Run shopify app init to scaffold the app (Remix-based recommended) using the Client ID/Secret from Prerequisite 1.1

Configure shopify.app.toml with app name, scopes (write_products not needed; use read_themes, write_themes, read_customers if needed for merge fields), and app URL

Run shopify app dev to connect to the dev store and confirm OAuth install works

Initialize a Git repository and push the scaffold to GitHub

Set up environment variable files (.env) for SHOPIFY_API_KEY, SHOPIFY_API_SECRET, SCOPES, HOST

DONE WHEN

The app installs on the dev store without errors and the default Remix "app home" page loads inside Shopify Admin.



DAY 2   Database & Backend Foundations

OBJECTIVE

Stand up the data layer and core backend structure that both the Theme Editor and Admin Dashboard will read/write.

TASKS

Provision Postgres (Prerequisite 1.2) and set DATABASE_URL

Define Prisma schema: Shop, Form, FormField, Submission, SubmissionValue, NotificationSetting, Integration, PlanUsage — fields per the Admin Dashboard and Theme Editor PRDs

Run prisma migrate dev to create initial tables

Scaffold backend route structure: /api/forms, /api/submissions, /api/templates (App Proxy-facing) and /app/* (Admin Dashboard-facing, session-authenticated)

Wire Shopify Billing API skeleton: three plans (Free/Starter/Growth) as GraphQL AppSubscription mutations, with a currentPlan() helper

DONE WHEN

Backend can create/read a Shop record on install and a test Form + FormField row can be inserted and queried via a temporary script.



DAY 3   Theme App Extension — Form Block Skeleton

OBJECTIVE

Get the root Form Block registering and rendering inside the Theme Editor, per Theme Editor PRD Sections 2 & 3.

TASKS

Run shopify app generate extension to scaffold a Theme App Extension

Create blocks/form.liquid with the container div (data-fbw-form-id) and a settings_schema covering Form Identity, Form Behaviour, Multi-Step, Spam Protection, and Accessibility groups (Theme Editor PRD §3.1–3.5)

Add the blocks whitelist array (empty for now — populated Day 4/5) so field blocks can nest inside it

Deploy the extension to the dev store and add the Form Block to a test page in the Theme Editor

DONE WHEN

The Form Block appears in the Theme Editor "Add block" list, can be added to a section, and its sidebar shows all Section 3 settings groups.



DAY 4   Field Block Types — Part 1 (Text-Family Fields)

OBJECTIVE

Build the reference field block (Text Input) and extend it to the other text-family types, per Theme Editor PRD §4.1–4.3, 4.11–4.12.

TASKS

Build blocks/field-text.liquid as the reference implementation with its full settings_schema (label, placeholder, help text, required, width, validation, autocomplete, field ID)

Extend to field-email.liquid, field-textarea.liquid, field-number.liquid, field-phone.liquid, field-url.liquid — each inheriting the base schema plus its documented additional settings

Whitelist all of these in the Form Block's blocks array

Confirm merchants can add each field type from the native "Add block" control and see the correct sidebar settings

DONE WHEN

All six text-family field types can be added inside the Form Block, each showing its own correct sidebar settings.



DAY 5   Field Block Types — Part 2 + Form Runtime JS

OBJECTIVE

Complete the remaining Free/Starter field types and get the storefront form actually rendering and submitting.

TASKS

Build field-dropdown.liquid, field-radio.liquid, field-checkbox.liquid, field-date.liquid, field-consent.liquid, field-hidden.liquid, field-section-heading.liquid, field-time.liquid, field-file.liquid (per Theme Editor PRD §4.4–4.10, 4.13, 4.15)

Build the Form Runtime JS bundle: reads the block's settings JSON, hydrates a live form, runs client-side validation (Theme Editor PRD §11), and POSTs to the App Proxy submission endpoint

Build the backend submission endpoint: validates server-side, writes a Submission + SubmissionValue rows, triggers the honeypot check

DONE WHEN

A full form with 5+ mixed field types can be filled out and submitted on the storefront preview, and the submission appears in the database.



DAY 6   Styling System

OBJECTIVE

Implement the CSS custom property architecture so every styling setting in the Theme Editor sidebar actually changes the rendered form.

TASKS

Implement the --fbw-* CSS custom property system scoped to #fbw-{blockId}, per Theme Editor PRD §14.3

Build the Form Block's Groups 4–9 styling settings (Container & Layout, Typography, Input Fields, Interactive Elements, Submit Button, Success Message) from the Form Design & Styling PRD property catalogue

Build the per-field "Customize style for this field" override toggle and state switcher (Default/Hover/Focus/Error/Disabled) described in Theme Editor PRD §6.2

Generate the scoped <style> block server-side (Liquid) or client-side (Form Runtime JS) from the settings JSON

DONE WHEN

Changing a color, font, or spacing setting in the sidebar visibly updates the storefront preview without a page reload delay beyond Shopify's normal Theme Editor refresh.



DAY 7   Design-Mode Overlay — Template Gallery & Field Picker

OBJECTIVE

Build the enriched creation experience that only appears inside the Theme Editor, per Theme Editor PRD §5.

TASKS

Build the design-mode JS bundle, loaded only when window.Shopify.designMode === true

Build the empty-state overlay (Browse Templates / Start Blank) shown when a Form Block has no fields yet

Build 5–8 seed templates in the backend (Prerequisite-free — just data) and the Template Gallery Modal that fetches and applies them via themeFilesUpsert

Build the in-canvas Visual Field Picker and hover controls (duplicate/delete/drag) described in §5.3–5.4

DONE WHEN

Adding a fresh Form Block shows the empty-state overlay, applying a template populates real field blocks, and hovering a field in canvas shows duplicate/delete controls.



DAY 8   Admin Dashboard (Embedded App)

OBJECTIVE

Build the merchant-facing management surface, per the Admin Dashboard PRD.

TASKS

Set up App Bridge v3 + Polaris shell with the left-nav structure (Dashboard, Forms, Submissions, Notifications, Integrations, Billing & Plan, Settings)

Build the Dashboard Overview page (metric cards, activity) and the Forms table page, reading from the Day 2 schema

Build the Submissions inbox page with per-form filtering

Wire the plan badge, over-limit banner, and trial countdown banner shell elements

DONE WHEN

Opening the app from Shopify Admin shows real forms and real submissions created in earlier days, not placeholder data.



DAY 9   Notifications, Plan Gating, Spam Protection & Billing

OBJECTIVE

Close the loop from submission to merchant notification, and enforce plan limits/locks across both surfaces.

TASKS

Wire the transactional email provider (Prerequisite 1.4) for merchant alert + customer auto-responder emails

Wire reCAPTCHA v3 (Prerequisite 1.4) as a Growth-gated toggle, scored server-side on submission

Implement plan-gate UX patterns from Theme Editor PRD §9 across locked field types, locked templates, and locked styling groups

Connect the Billing API plan changes to actually unlock/lock the relevant features in real time

Stub the Klaviyo/Google Sheets integration UI (Integrations page) with "Connect" buttons; wire real API calls only if Prerequisite keys were provided

DONE WHEN

Submitting a form sends a real notification email, a low-score reCAPTCHA submission is flagged, and downgrading the test shop to Free visibly locks Growth-only features in both the Theme Editor and Dashboard.



DAY 10   End-to-End Testing, Compliance Stubs & Polish

OBJECTIVE

Verify the full merchant + customer journey and put the mandatory compliance pieces in place.

TASKS

Full walkthrough: install app → apply a template → customize fields and styling → publish theme → submit as a customer → confirm submission, email, and dashboard entry all match

Test multi-step mode and (if built) conditional logic show/hide behaviour

Accessibility pass: keyboard navigation through the field picker, aria-live error announcements, focus-first-error behaviour

Implement the three mandatory GDPR webhooks (customers/data_request, customers/redact, shop/redact) as stubs that log and return 200

Write a short internal README covering environment variables, deploy steps, and known gaps for Day 11+

DONE WHEN

A form can be created from scratch and fully tested end-to-end without manual database edits, and the app has no unhandled errors in the Shopify Partner Dashboard app logs.





4.  Day 11+ — Deferred Work

Not required to have a working, testable app after Day 10, but required before a public App Store launch:

Full Klaviyo, Google Sheets, and Zapier integrations (real OAuth flows, field mapping UI)

Rating/NPS and Signature field types fully built out (can ship after Day 10 without blocking the rest of the app)

Conditional logic full rule engine if only stubbed during the 10 days

Load testing, rate limiting on the App Proxy submission endpoint

Privacy policy, support contact, and listing assets for Shopify App Store review

Filling in the real logic behind the GDPR webhook stubs (actually deleting/exporting data)

Dark mode styling variants and advanced responsive breakpoint controls (Starter+ Advanced group)
