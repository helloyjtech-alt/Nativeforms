

PRODUCT REQUIREMENTS DOCUMENT

Form Design & Styling System

Custom Form Builder — Shopify App

Version 1.0  |  2026





1. Overview

This PRD defines every styling option exposed to merchants in the Custom Form Builder Shopify app. The styling system covers two levels of control:

Global (Form-level) — styles applied to the entire form block as defaults. Every field inherits these unless overridden.

Individual (Field-level) — per-field overrides that activate only when the merchant explicitly enables "Customize this field."

All style controls are surfaced as native Shopify Theme Editor sidebar settings (no custom CSS knowledge required). An Advanced / raw CSS escape hatch is also provided at both levels for merchants on the Growth plan.



2. Scope of Elements

The styling system covers the following UI elements:

Form Section Wrapper (outermost container inserted by the theme block)

Form Inner Container (the card/box that visually wraps the form)

Form Header area (title, subtitle)

Field Row / Column layout wrapper

Labels

Input fields — text, email, number, URL, password, hidden (all share one set of input styles)

Textarea (Long Text)

Custom Select (built as <div> + <span>, not a native <select>)

Dropdown option list and individual option items

Radio Group wrapper + individual Radio item

Checkbox Group wrapper + individual Checkbox item

Date Picker field

File Upload field

Consent / legal Checkbox

Section Heading (divider label within the form)

Star / Rating widget

Custom Placeholder (rendered as <span> inside the field, not native placeholder)

Help Text / Description

Validation Error message

Submit Button

Success / Thank-you message block

Progress Bar (multi-step forms)



3. Architecture — Two-Level Style System

3.1  Global Form Styles (inherited by all fields)

Set on the root Custom Form Builder block in the Theme Editor sidebar. All fields inherit these values unless overridden at the field level. Changing a global setting updates every field that has not been individually overridden — live in the Theme Editor preview.



3.2  Field-Level Style Override

Each field block exposes a "Customize style for this field" toggle (off by default). When enabled, the sidebar reveals a compact override panel. Only the properties a merchant touches in this panel are written to that field's settings; everything else continues to inherit from global. This means merchants only need to override what's genuinely different for one specific field.



3.3  Hover / Focus / Active / Disabled States

Both global and field-level panels include a State sub-section. A segmented control lets the merchant switch the sidebar into Default | Hover | Focus | Error | Disabled view — the controls shown are the same set but write to state-specific CSS custom properties (e.g. --fbw-input-border-color-hover). The live canvas preview enters that state on the hovered/focused demo field so merchants see the effect instantly.

6. Advanced — Raw Custom CSS (Growth Plan)

Available at both Form level and individual Field level for merchants on the Growth plan. The raw CSS textarea accepts any valid CSS, automatically scoped to the unique block/field ID to prevent it bleeding outside the form. A syntax-highlighted code editor is shown in the Theme Editor sidebar.



Form-level raw CSS: scoped to #fbw-{blockId} — applies to the entire form and all its children

Field-level raw CSS: scoped to #fbw-{blockId} .fbw-field-{fieldId} — applies only to that one field

CSS variables (custom properties): all design tokens are exposed as --fbw-* CSS variables so merchants can override one value and have it cascade automatically

Syntax: standard CSS — no SCSS, no nesting (CSS nesting will be supported when browser support matures)

Live preview updates in real-time as the merchant types (debounced 300 ms)

Note: Custom CSS is not validated for safety (it runs in the storefront). Malicious input can only affect the merchant's own storefront. This is standard practice for Shopify theme customization.

8. Items Not Yet Mentioned — Recommended Additions

The following are styling system concerns not explicitly listed in the brief but required for a complete, professional-grade form builder:



8.1  CSS Custom Properties (Design Token Panel)

All style values should write to CSS custom properties (--fbw-*) on the block root element, not hard-coded inline styles

This allows merchants to use the same variable in multiple places and change it in one click

Expose a "Tokens" view in the Advanced section showing all variable names for developer reference

8.2  Responsive Breakpoints

Every sizing property (height, padding, font-size, etc.) should have Mobile and Desktop tabs in the sidebar

Mobile styles use a CSS @media query — no extra work for merchants, controlled by the same picker

8.3  Dark Mode Support

Each color control exposes a "Dark mode variant" — shown as a secondary color swatch next to the main one

Dark mode colors write to a [data-color-scheme="dark"] or @media (prefers-color-scheme: dark) scoped rule

8.4  Form Animation / Entrance Effects

Scroll-triggered or load-triggered entrance for the form container: Fade in / Slide up / None

Animation duration + delay + easing for the container entrance

8.5  Multi-Step Navigation Buttons

"Next" and "Back" buttons in multi-step forms need independent styling from the Submit button

Same full button style set from Section 4.14, but as a separate "Navigation Buttons" group

8.6  Required Field Indicator

Asterisk (*) or custom symbol color and position (after label vs before label)

Option to show "required" / "optional" text badge instead of asterisk

8.7  Character Count / Counter Display

Text color, font size, alignment, and position (below input vs inline right) for the character counter

8.8  Inline Validation Styling

Success state (green border + checkmark) separate from the error state — for real-time validation feedback

Success checkmark icon color and size

8.9  Field Focus Order / Tab Highlight

High-visibility focus ring for accessibility — separate from the hover state, controlled independently

Focus ring color, width, offset, style (solid / dashed / glow)

8.10  Print Styles

A "Print-friendly mode" toggle that strips backgrounds, shadows, and colors for clean printing

10. Implementation Notes (UX/Architecture)

All styling controls are Shopify native settings_schema entries — no custom sidebar UI is required. This ensures future compatibility with Shopify updates.

CSS is generated at render time on the storefront by the app's Liquid/JS runtime, converting the stored settings into a <style> block scoped to the form block ID.

Every color control supports transparency/alpha via a color picker with an opacity slider.

Linked/unlinked padding controls: a small chain-link icon lets merchants lock all four sides together or break them individually — this is the same UX as native Shopify section spacing controls.

The sidebar state-switcher (Default | Hover | Focus | Error | Disabled) is a custom Theme Editor block action bar rendered above the standard settings controls.

Placeholder spans are positioned via position: absolute inside a position: relative wrapper on the field, with z-index managed to not overlap real text.

Custom Select triggers a custom [data-open] attribute toggle, allowing CSS-only open/close animation without a JS transition API, which keeps animations hardware-accelerated via transform and opacity.

All animation durations exposed in the sidebar write to CSS custom properties, meaning a single --fbw-transition-duration variable controls every transition in the form when set globally.
