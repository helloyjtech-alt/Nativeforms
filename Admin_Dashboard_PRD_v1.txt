

PRODUCT REQUIREMENTS DOCUMENT

Admin Dashboard

Custom Form Builder — Shopify App

Version 1.0  ·  All Pages & Features  ·  Including Billing & Plans





1.  Purpose & Scope

This document defines every page, module, component, user interaction, and feature gate inside the Custom Form Builder embedded Admin Dashboard. The Dashboard lives inside Shopify's Admin chrome (App Bridge v3 + Polaris), not in a separate browser window. Its purpose is management and visibility — form construction happens entirely in the Shopify Theme Editor and is never duplicated here.

What this PRD covers:

Every named page and sub-page in the left navigation

Every UI component on each page — tables, cards, charts, modals, drawers, banners

Every user action — clicks, filters, exports, bulk operations

Every plan-gate — which features are Free / Starter / Growth

The Billing & Plans page in full detail

Empty states, error states, over-limit banners

Notification and alert flows triggered from the Dashboard

3.2  Submissions Activity Chart

Line chart (Recharts / Polaris Charts). X-axis: date. Y-axis: submission count. Three toggle buttons above the chart: 7 Days / 30 Days / 90 Days. Each form is a separate coloured line; a legend maps colour to form name. Hovering a data point shows a tooltip: date, form name, submission count for that day.

If merchant has 0 forms: chart area is replaced by an empty-state illustration with "Add your first form in the Theme Editor" + button.

If all forms have 0 submissions: chart renders with flat zero line + "No submissions yet" overlay label.



3.3  Recent Submissions Feed

A list of the 5 most recent submissions across all forms. Each row shows: Status dot (Unread = blue, Read = grey), Submitter name/email (first value that looks like a name/email), Form name, Time ago ("2 hours ago"), and a "View" link. Clicking "View" opens the Submission Detail drawer (Section 5.3). A "View all submissions" link at the bottom navigates to the Submissions page.



3.4  Quick-Start Cards (new installs only)

Shown above the metric cards for the first 7 days after install, or until the merchant dismisses them. Three cards in a row:

Add your first form — "Open Theme Editor" deep-link button. Card disappears after the first form is created.

Set up notifications — links to Notifications page. Card disappears after a notification email is saved.

Explore templates — links to the Template Gallery (opens in Theme Editor context). Always dismissible manually.

4.5  Form Detail Page

Route: /forms/:id. Accessed by clicking the form name in the table. Four tabs across the top:



Tab A: Overview & Analytics

Form info card — Name, Status badge, Created date, Theme block ID, Field count. "Edit in Theme Editor" primary button.

Same Submissions data grid as Section 5 but pre-filtered to this form. Includes search, status filter, date range filter, and CSV export — all scoped to this form.



Tab C: Notification Settings

Per-form email configuration (overrides the global Notifications defaults for this specific form):

Merchant alert email — text input for the recipient address. Default pulls from global Settings. "Send to multiple" — comma-separated.

Reply-to field — sets the Reply-To header so merchant can reply directly to the submitter.

Email subject line — text input. Supports variables: {{form.title}}, {{submission.id}}, {{date}}.

Merchant alert email body — rich text editor with variable picker. Available variables: {{form.title}}, {{submission.id}}, {{submission.date}}, {{fields.*}} for each field. "Preview" button renders a live HTML preview in a modal.

Customer auto-responder toggle — ON/OFF. When ON:

Email address field to pull from — dropdown of all Email-type fields on this form.

Auto-responder subject — text input with variable support.

Auto-responder body — rich text editor with variable picker.

Preview button.

"Send test email" button — fires a test alert to the configured merchant address with dummy field values. Shows a success/error toast.

Plan gate: auto-responder requires Starter+. On Free, the auto-responder section is visible but controls are locked with an "Upgrade to Starter" inline upsell.



Tab D: Danger Zone

Archive this form — same as table row action. Amber confirmation banner.

Delete this form — red "Delete" button. Two-step modal: shows submission count that will be permanently deleted, requires typing form name to confirm.

Export all submissions — exports all submissions for this form as CSV. Bypasses the inbox filter.

8.4  Upgrade / Downgrade Flow

Upgrade CTA button on the plan card triggers: App Backend -> appSubscriptionCreate (Shopify Billing API) -> merchant redirected to Shopify's hosted billing confirmation page -> on approval, redirect back to /billing?upgraded=true -> success banner "You're now on [PLAN]. Your new features are active."

Annual switch: same flow as upgrade but with ANNUAL interval.

Downgrade: shows a modal listing features that will be lost and any forms/submissions that will be affected (e.g. "2 forms will be archived as you'll exceed the Free limit"). Requires merchant to type "DOWNGRADE" to confirm. Downgrade is processed at end of current billing period, not immediately.

Cancellation: "Cancel subscription" link at the bottom of the current plan card. Confirmation modal. Subscription ends at period end, plan reverts to Free. Forms above Free cap are archived, not deleted.



8.5  Invoice History

Table below the plan cards. Columns: Date, Description ("Starter Monthly"), Amount, Status (Paid / Failed / Refunded), PDF link. Data pulled from Shopify's appSubscription billing records. Paginated 10 per page. "Download all as PDF" at the top of the table. If no invoices: "No billing history yet."

11.  Onboarding Flow (Post-Install)

The first-run experience after OAuth install. Designed to get the merchant to their first live form in under 3 minutes.



11.1  Steps



Onboarding Step

What Happens

Step 1 — Welcome screen

Full-width welcome card. App name, one-sentence value prop. Three quick-start cards (Section 3.4). "Get started" button scrolls to metric cards.

Step 2 — Merchant clicks "Add your first form"

Backend calls themeFilesUpsert to inject an empty Form block into the current published theme. Deep-link to Theme Editor is opened. A "You're almost there" toast shows in the Admin.

Step 3 — Inside Theme Editor

The merchant sees the empty Form block with the design-mode gallery overlay (handled by the theme extension, not the Admin). They choose a template or start blank.

Step 4 — Back in Admin

Once the form is saved in the Theme Editor and the merchant returns, the Dashboard refreshes. The form appears in the Forms table. Quick-start cards begin collapsing as tasks are completed.

Step 5 — Notifications prompt

Second quick-start card links to /notifications. A guided tooltip draws attention to the "Default recipient email" field.

Step 6 — Completion

After 3 tasks complete (form created, notification saved, first submission received), a "You're set up!" banner replaces the quick-start cards. Includes a one-click "Upgrade to Starter" nudge.

14.  Inline Upsell Moments

Every gated feature in the Admin shows an in-context upsell rather than a dead end. Design principle: the upsell must appear inside the feature's own space, never redirect away from the current task.



Trigger / Location

Upsell Message & Action

Submissions table — export row limit hit

"You've reached the 100-row export limit. Upgrade to Starter for up to 1,000 rows, or Growth for 10,000." Button: Upgrade.

Notification page — auto-responder section (Free)

Grey card: "Customer auto-responders are available on Starter and Growth. Automatically send a confirmation email to everyone who fills out your form." Button: Upgrade to Starter.

Integrations page (Free or Starter)

Overlay card on each locked integration: "[Integration] is available on the Growth plan. Connect your submissions to your marketing stack automatically." Button: Upgrade to Growth.

Forms table — at plan limit (Free: 2, Starter: 10)

Row at the bottom of the table: "You've used X of X forms on the [PLAN] plan. Upgrade to [next plan] to create more." Button: Upgrade.

Settings — Remove branding toggle (Free)

Toggle is visible but disabled. Tooltip on hover: "Remove branding on Starter and Growth plans." Clicking the disabled toggle opens a small popover with upgrade CTA.

Submission detail — IP address (Free/Starter)

IP field shows "192.168.1.***" with a tooltip: "Full IP addresses are available on the Growth plan for compliance and spam management."

File uploads (Free)

If a File Upload field is added in the Theme Editor, the submission detail shows a "File uploads require Starter+" notice instead of the file link.





15.  Gaps & Recommended Additions Not in Original Spec

Items not explicitly specified in the Master Architecture v2 but required for a complete, professional embedded Shopify app:



15.1  Activity / Audit Log

A log of significant admin events visible in the Dashboard or Settings: "Form [name] archived by store owner · 2 hours ago", "Plan upgraded to Starter · yesterday", "Integration [Klaviyo] connected · 3 days ago." Essential for shops with multiple staff members.



15.2  Email Deliverability Status

A status widget in the Notifications page showing whether the last 5 alert emails were delivered, bounced, or failed (pulled from email provider webhook). "Last email sent: 2 hours ago · Delivered." Catches misconfigured email addresses before the merchant notices.



15.3  Submission Spam Rate Card

A small card on the Dashboard showing: "Spam blocked this month: X." Reinforces the value of the app's spam protection and creates an upsell hook toward reCAPTCHA (Growth).



15.4  Per-Form Submission Notification Frequency Control

An option in the Form Detail > Notification Settings to set the merchant alert to: "Every submission" / "Daily digest" / "Weekly digest." High-volume forms can flood a merchant's inbox — a digest option prevents unsubscribes from their own notification emails.



15.5  Staff Accounts / Role Separation

On Shopify, each staff member has their own Admin login. The app should respect Shopify's staff permissions: if a staff member doesn't have billing permissions, the Billing page should show "Contact your store owner to manage the plan" instead of the upgrade flow.



15.6  Dark Mode

Shopify Admin supports dark mode. Polaris handles this automatically for native components, but any custom SVG illustrations, chart colours, and custom banners should have explicit dark-mode variants so the app doesn't look broken in dark theme.



15.7  Mobile Responsiveness

Shopify Admin is used on mobile. The Dashboard overview cards should stack 2x2 then 1x4 on small screens. The submissions table should collapse to a card list view on mobile. The Billing plan cards should stack vertically.
